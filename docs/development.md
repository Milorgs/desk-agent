# 开发记录

## 2026-11-04 · v0.1.0

本项目来自参赛者与 AI 的真实讨论：选择 Linux CLI 电脑助手，通过可配置模型 API，支持文件编辑、终端任务和桌面操作。参赛者明确要求独立实现，不包装 agent-desktop，并在每个可运行版本完成后上传 GitHub。

### 本次实现

1. 建立 Python 包和命令行入口、API 配置与兼容 Chat Completions 的传输层。
2. 实现模型/工具执行循环、文件 SHA256 冲突检测和备份、限时 Shell，以及 AT-SPI 语义控件适配。
3. 添加自动测试、CI、使用文档与可选本地对话记录。

### 当前验证证据

- 当前开发环境：Arch Linux / KDE / Wayland，Python 3.14.9。
- `--help`、`doctor`、模块编译通过；GI 的 Atspi 2.0 可加载。
- 本地自动测试通过，含模拟 HTTP 服务的文件创建/读回流程。
- 尚无真实模型 API 联调结果，也未实际操作用户桌面验证。不能将模拟测试描述成真实 AI 控制电脑成功。

### 过程材料说明

## 2026-11-04 · v0.2.0

用户反馈 v0.1 的模块命令、环境变量和一次性调用不方便，希望有类似 Codex CLI 的日常使用体验。本轮围绕这一真实反馈修改：

- `desk` 无参数进入持续对话，保留会话上下文，支持 `/new`、`/config`、`/status`、`/desktop`、`/permissions`、`/exit`。
- 首次自动引导配置，密钥通过隐藏输入保存到本机权限 600 的 auth.json，不再每次设置环境变量。
- 命令工具默认提供，执行仍需确认；桌面工具可在会话内开启。
- 新增无需 pip/root 的安装器，可从任意目录运行 desk。
- 中断或拒绝批量工具调用后补齐未执行调用的结果，避免下一轮对话因悬空工具调用失败。
- 新增首次引导、私有配置、上下文延续/清空、中断继续和独立安装测试。共 16 项本地测试通过。

本轮依然未配置真实模型密钥；交互流程测试使用明确标识的模拟模型，不宣称完成真实 AI 桌面操作验收。


## 2026-11-04 · v0.3.0

用户明确希望改进 API 的多服务商、多模型切换。本轮增加：

- 配置修改跨 API 主机时要求输入新密钥；指定 `--provider` 时不应用环境变量覆盖。
- 新增独立密钥、旧配置迁移、跨服务商会话隔离、切换模型持久化、最小连接测试和 HTTP 错误场景测试。

## 2026-11-04 · 1.0.0 纯 C 重写

- 构建使用 Make 和系统 C 开发库；安装器为 POSIX Shell，直接安装 ELF 可执行文件，不需要 Python。
- 同时支持 OpenAI Chat Completions 与 Anthropic Messages，保留原菜单、接口标签及操作确认流程。
- C 迁移器读取旧程序生成的 TOML 和独立密钥文件，后续原子保存到私有 settings.json；旧文件保留。
- 编写本地 C HTTP 模拟服务验证创建文件、读取结果、多工具结果合并及原生签名内容回传。
- 执行编译警告检查、AddressSanitizer 和 UndefinedBehaviorSanitizer 检查。
- Python 文件从当前源码移除，历史仍可在旧提交查看。此前 Python/C 的短命令基准仅对应 0.6.0，不作为本次重写的性能结论。

## 2026-11-04 · 1.1.0

改进 agent 的定位、编辑、执行反馈和失败恢复，并按用户要求迁移到 C++20。

- 全部应用模块和测试使用 C++ 编译器构建；保留 libcurl、json-c、OpenSSL 与可选 AT-SPI 的系统接口，不增加脚本运行时。
- API 响应和命令输出使用 std::string，子进程环境使用 std::vector，局部编辑和 JSON 所有权使用 RAII；失败记录与重复调用观察使用类型化容器。
- 新增有预算的 search_text，返回路径、行号、文本片段、跳过与截断信息；先定位再读取，避免盲猜文件。
- 新增 edit_file，只替换唯一的精确匹配，复用 SHA256 冲突检查、确认、备份和原子写入；写入后回读核对字节。
- 系统提示和工具参数说明明确独立命令环境、失败诊断、桌面重新读取，以及验证用户目标的要求。
- 无关读取不清除失败；失败的写入只能被同一目标的后续修改恢复。重复且无变化的读取停止，剩余批量调用补齐未执行结果。
- 严格检查整轮工具调用的 JSON 对象，避免第二个调用损坏时已经执行第一个；独立校验 UTF-8 并用等价 Unicode 转义兼容 json-c 0.18 的严格模式，中文与 emoji 参数均参与回归。Anthropic 对非零退出和超时也标记 is_error。
- 终端显示操作目标、命令、输出预览、退出码、用时与本轮统计；菜单、安装输出和 README 以功能为主。
- 安装器兼容旧安装标记，后续写入通用标记，原菜单编号、模型配置、API 协议和 desk 命令保持兼容。

按用户要求收起默认操作过程：终端只更新一行“正在思考 / 读取 / 编辑 / 执行”等活动提示，操作完成后显示最终回复；详细工具参数、文件正文、命令输出和模型工具阶段的说明默认隐藏。完整消息和工具结果保留在内部历史，只有显式 `--verbose` 才展开详细过程。失败提示继续可见。

前台批准默认显示操作摘要，数字 3 可展开完整操作；选择允许或拒绝前仍可审阅。自动批准不再输出整个文件修改预览。后台任务沿用启动时的详细输出设置。

交互退出统一为 Ctrl+D：聊天空行继续输入，0 作为普通需求；主菜单 0 只提示退出按键，不结束程序。Ctrl+C 取消当前操作后保留聊天。输入结束状态跨菜单与批准提示传播；Linux 能在等待 API、退避和长命令期间检查终端 EOF，及时取消请求、清理命令进程组并退出，不消费排队中的普通请求文字。数字菜单提供返回主菜单的导航选项。
