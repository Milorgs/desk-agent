# 开发记录

## 2026-11-04 · v0.1.0

本项目来自参赛者与 AI 的真实讨论：选择 Linux CLI 电脑助手，通过可配置模型 API，支持文件编辑、终端任务和桌面操作。参赛者明确要求独立实现，不包装 agent-desktop，并在每个可运行版本完成后上传 GitHub。

### 本次实现

1. 建立 Python 包和命令行入口、API 配置与兼容 Chat Completions 的传输层。
2. 实现模型/工具执行循环、文件 SHA256 冲突检测和备份、限时 Shell，以及 AT-SPI 语义控件适配。
3. 添加自动测试、CI、使用文档与可选本地对话记录。

### 当前验证证据

- 当前开发环境：Arch Linux / KDE / Wayland，Python 3.14.9。
- `--help`、`doctor`、模块编译通过；GI 的 Atspi 2.0 可加载。
- 本地自动测试通过，含模拟 HTTP 服务的文件创建/读回流程。
- 尚无真实模型 API 联调结果，也未实际操作用户桌面验证。不能将模拟测试描述成真实 AI 控制电脑成功。

### 过程材料说明

本文是开发摘要，不是原始 Prompt 对话，不替代比赛要求的完整 AI 对话链。应保留本次聊天原始记录，按真实情况导出或截图。禁止事后编造对话或补造功能迭代。软件自身的 `--record` 只记录使用该软件执行任务的会话，不包含本次开发聊天。

### 下一版候选

- 在指定 KDE 应用中验证 AT-SPI 能力并补充适配。

## 2026-11-04 · v0.2.0

用户反馈 v0.1 的模块命令、环境变量和一次性调用不方便，希望有类似 Codex CLI 的日常使用体验。本轮围绕这一真实反馈修改：

- `desk` 无参数进入持续对话，保留会话上下文，支持 `/new`、`/config`、`/status`、`/desktop`、`/permissions`、`/exit`。
- 首次自动引导配置，密钥通过隐藏输入保存到本机权限 600 的 auth.json，不再每次设置环境变量。
- 命令工具默认提供，执行仍需确认；桌面工具可在会话内开启。
- 新增无需 pip/root 的安装器，可从任意目录运行 desk。
- 中断或拒绝批量工具调用后补齐未执行调用的结果，避免下一轮对话因悬空工具调用失败。
- 新增首次引导、私有配置、上下文延续/清空、中断继续和独立安装测试。共 16 项本地测试通过。

本轮依然未配置真实模型密钥；交互流程测试使用明确标识的模拟模型，不宣称完成真实 AI 桌面操作验收。


## 2026-11-04 · v0.3.0

用户明确希望改进 API 的多服务商、多模型切换。本轮增加：

- 每套配置独立保存 Base URL、密钥和默认模型，保留旧版 default 配置。
- `/provider` 列出、添加、切换服务商，`/model` 获取列表和切换模型，`/test` 检查连接与工具调用。
- 切换后重置上下文；不自动把会话故障转移给其他服务商。
- 完整 Chat Completions 地址规范化、按状态码提示错误、短暂服务端错误的有限重试；网络超时不自动重试。
- 配置修改跨 API 主机时要求输入新密钥；指定 `--provider` 时不应用环境变量覆盖。
- 新增独立密钥、旧配置迁移、跨服务商会话隔离、切换模型持久化、最小连接测试和 HTTP 错误场景测试。

仍使用本地模拟服务验证 HTTP 协议，没有读取或使用用户的真实密钥，也未声称完成实际服务商联调。


## 2026-11-04 · v0.4.0

用户进一步提出 Anthropic 接口支持。本轮直接适配原生 Messages API，不要求服务商转换成 OpenAI 格式：

- 每套 provider 增加 protocol，支持 openai / anthropic；旧配置缺省仍为 openai。
- 配置向导选择接口，状态显示实际协议，模型切换保留协议、生成上限和 API 版本。
- 原生认证请求头、顶层 system、工具 input_schema、tool_use/tool_result，以及同轮多个工具结果的合并。
- 工具续接时原样保留 thinking/redacted_thinking 内容块及签名，不显示为终端回答。
- 原生模型列表及无副作用连接测试。Anthropic 使用 auto 工具选择，不强制依赖部分模型不支持的 forced tool choice。
- 拒绝、截断、无效工具参数或未知内容块均在本地工具执行前停止。
- 版本 header 默认固定 2023-06-01，允许配置覆盖；参考官方版本历史确认其仍受支持。

本地共 37 项自动测试通过，包括模拟 Anthropic HTTP 服务的真实文件创建/读取循环。尚未使用真实 Anthropic API Key 联调，不宣称第三方代理均可兼容。


## 2026-11-04 · v0.5.0

用户明确指定启动后的菜单顺序为 `[1] 开始对话`、`[2] 选择模型`、`[3] 添加模型`，本轮按最终要求实现，另保留 `[0] 退出`。

- 交互终端直接运行 desk 先显示菜单，无配置时不会自动进入填写流程。
- 添加模型逐项引导，支持中文配置名称、自动命名、OpenAI / Anthropic 编号选择。
- 已保存模型按编号选择，不会在选择列表时调用模型 API。
- `/menu` 从对话返回菜单并保留上下文；选用或添加不同配置后重置会话。
- 保留单次任务调用和非交互输入，不向自动化调用插入菜单。
- 新增首次空配置退出、缺少模型时引导、编号选择、中文命名、取消与中断、上下文保留/清空和单次任务兼容测试；共 46 项本地自动测试通过。

本轮只改变命令行交互，不把此前的模拟 API 测试描述为真实服务商调用。

## 2026-11-04 · v0.6.0

用户要求尝试优化逻辑，并明确也要试 C。本轮保留其手动修改的 OpenAI接口 / Anthropic接口 名称，拆分原 cli.py 中的菜单、配置向导、对话控制和记录代码。

- 增加任务状态、取消后工具结果修复、重复工具编号校验；非零命令退出与超时计入失败。

- 配置向导增加“测试连接并保存 / 直接保存 / 取消”，失败时不覆盖原设置。
- 独立编写 C 命令执行器，加入可选 --shell-backend c 和 --with-native 构建安装；默认仍为 Python。
- 两个后端对照验证中文和二进制输出、退出码、截断、超时、进程组终止和环境变量过滤。C 故障不自动重跑命令。

- 自动测试增加配置测试失败保留旧配置、任务状态、上下文完整性、C 后端和原生安装覆盖。

本轮没有使用用户真实 API Key 发送模型请求；上述端到端工具循环仍是明示的模拟接口测试。

## 2026-11-04 · 1.0.0 纯 C 重写

用户明确要求直接使用 C，放弃 Python。本轮将菜单、模型配置、HTTP/API、任务循环、文件工具、进程管理、桌面适配和测试全部改为 C。

- 构建使用 Make 和系统 C 开发库；安装器为 POSIX Shell，直接安装 ELF 可执行文件，不需要 Python。
- 同时支持 OpenAI Chat Completions 与 Anthropic Messages，保留原菜单、接口标签及操作确认流程。
- C 迁移器读取旧程序生成的 TOML 和独立密钥文件，后续原子保存到私有 settings.json；旧文件保留。
- 编写本地 C HTTP 模拟服务验证创建文件、读取结果、多工具结果合并及原生签名内容回传。
- 执行编译警告检查、AddressSanitizer 和 UndefinedBehaviorSanitizer 检查。
- Python 文件从当前源码移除，历史仍可在旧提交查看。此前 Python/C 的短命令基准仅对应 0.6.0，不作为本次重写的性能结论。

未使用真实 API 密钥发出请求；真实服务商与桌面操作仍需使用者环境联调。


## 2026-11-04 · 1.1.0

改进 agent 的定位、编辑、执行反馈和失败恢复，并按用户要求迁移到 C++20。

- 全部应用模块和测试使用 C++ 编译器构建；保留 libcurl、json-c、OpenSSL 与可选 AT-SPI 的系统接口，不增加脚本运行时。
- API 响应和命令输出使用 std::string，子进程环境使用 std::vector，局部编辑和 JSON 所有权使用 RAII；失败记录与重复调用观察使用类型化容器。
- 新增有预算的 search_text，返回路径、行号、文本片段、跳过与截断信息；先定位再读取，避免盲猜文件。
- 新增 edit_file，只替换唯一的精确匹配，复用 SHA256 冲突检查、确认、备份和原子写入；写入后回读核对字节。
- 系统提示和工具参数说明明确独立命令环境、失败诊断、桌面重新读取，以及验证用户目标的要求。
- 无关读取不清除失败；失败的写入只能被同一目标的后续修改恢复。重复且无变化的读取停止，剩余批量调用补齐未执行结果。
- 严格检查整轮工具调用的 JSON 对象，避免第二个调用损坏时已经执行第一个；独立校验 UTF-8 并用等价 Unicode 转义兼容 json-c 0.18 的严格模式，中文与 emoji 参数均参与回归。Anthropic 对非零退出和超时也标记 is_error。
- 终端显示操作目标、命令、输出预览、退出码、用时与本轮统计；菜单、安装输出和 README 以功能为主。
- 安装器兼容旧安装标记，后续写入通用标记，原菜单编号、模型配置、API 协议和 desk 命令保持兼容。

本地 320 项检查通过，同时通过 AddressSanitizer、UndefinedBehaviorSanitizer 与强化编译检查。验证采用本地模拟 HTTP 服务，不发送用户真实密钥；真实模型行为和真实桌面端到端仍需用户环境联调。

## 2026-11-05 · 1.2.0

增加 CLI 多任务并行：最多 4 个活动任务，独立工作进程、PTY、模型配置和会话。提供新建、列表、切换、单独取消及保留上下文继续任务；任务输出在内存限长保存，等待主界面输入时持续排空后台输出。确认在所选任务终端完成，不自动批准后台操作。

配置使用本机匿名管道传递，不新建密钥文件或携带密钥的命令行参数。退出对话时停止并回收工作进程。同目录修改与命令使用文件锁协调，不同工作目录可并行执行命令；开启桌面功能的任务使用用户级独占锁。锁不替代外部程序隔离。

本地模拟 HTTP 服务设置双请求屏障，验证真实并行请求、上下文隔离与继续对话；PTY 测试验证切换到任务后确认写入。另覆盖等待确认取消、子进程清理、共享目录锁和不同目录进展。实际付费 API 与图形桌面未在本轮执行。

本轮本地 428 项检查通过，包含并行屏障、上下文继续、终端确认和资源锁；AddressSanitizer 与 UndefinedBehaviorSanitizer 检查通过。
